# 七层防护详解

secret-management的七层防护，从最外层（暴力破解）到最内层（文件权限），层层递进。

## L1 · Argon2id 密钥派生

**作用**：把主密码变成加密密钥。

```
密码 "my_master_password"
  ↓ Argon2id（time_cost=4, memory_cost=64MB, parallelism=2）
密钥 [32字节]
```

**为什么用 Argon2id 而非 PBKDF2/bcrypt？**

| 算法 | 抗 GPU | 抗 ASIC | 内存占用 |
|:---|:---|:---|:---|
| PBKDF2 | ❌ | ❌ | 低 |
| bcrypt | ⚠️ | ❌ | 低 |
| **Argon2id** | ✅ | ✅ | 高（可调） |

Argon2id 强制每次派生占用固定内存（如 64MB），GPU/ASIC 无法通过并行大规模加速。

**攻击成本**：48 位随机密码 → 每次派生 0.5 秒 → 破解需 10^28 年。

## L2 · SHA-384 完整性哈希

**作用**：检测密文是否被篡改。

```
存储时: 明文 → SHA-384 → hash 一起存
读取时: 重新计算 SHA-384 → 比对
        不匹配 → 密文被改 → 拒绝解密
```

**为什么用 SHA-384 而非 MD5/SHA-1**：MD5/SHA-1 已被碰撞攻击破解，SHA-384 目前安全。

## L3 · 硬件指纹绑定

**作用**：密文复制到其他服务器即失效。

**采集四个值**：
1. MAC 地址（网卡物理地址）
2. 机器 ID（/etc/machine-id）
3. 主机名
4. 内核版本

**混合逻辑**：
```
指纹 = SHA256(machine-id)[:16] + SHA256(hostname)[:16] + SHA256(kernel)[:16] + SHA256(mac)[:16]
```

**加密时**：指纹混入密钥派生
**解密时**：重新采集比对，不匹配 → 拒绝

**局限**：换网卡/换内核/重装系统都会改变指纹。需提前备份并重建 hw.bin。

## L4 · Fernet AES 对称加密

**作用**：加密数据本体。

Fernet = AES-128-CBC（加密）+ HMAC-SHA256（认证）。

```
明文 → AES-128-CBC 加密 → 密文
      → HMAC-SHA256 签名 → 认证标签
```

解密前先验证 HMAC，防密文被篡改。

## L5 · ECC P-384 数字签名

**作用**：验证密文确实由本机生成，防替换。

```
存储时: 用 ECC 私钥签名 → 指纹
读取时: 用 ECC 公钥验证 → 不匹配 = 密文被替换
```

ECC P-384 提供 192 位安全性，破解需 2^192 次计算。

## L6 · 假文件完整性校验

**作用**：目录被清理/篡改时自动锁死。

```
伪装目录 /root/mytp/:
  package.json, README.md, src/index.js, lib/crypto.py, data/cache.db ...（10个假文件）

首次访问 → hash 所有假文件 → 存 decoy.hash
每次访问 → 重新 hash 比对 → 不匹配 = 锁死
```

**攻击者踩坑**：清理日志/临时文件时，误删假文件 → 密钥库锁死。

## L7 · 文件权限隔离

**作用**：非 root 用户无法读取。

```
vault.enc   → chmod 600（仅 owner 可读）
.keys/      → chmod 700（仅 owner 可进入）
keymgr      → chmod 700（仅 owner 可执行）
```

即使攻击者拿到普通用户 shell，也无法读取密钥文件。

## 组合效果

```
攻击者尝试          → 撞哪层
暴力破解密码        → L1 Argon2id
篡改密文           → L2 SHA-384 + L4 HMAC
复制到别的服务器    → L3 硬件指纹
替换密文           → L5 ECC 签名
清理目录           → L6 假文件校验
非root读取         → L7 文件权限
```

七层独立生效，任何一层被绕过，其他层仍有效。
